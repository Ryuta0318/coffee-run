# Handoff: COFFEE RUN（社内コーヒー共同注文・PayPay精算）

## Overview
社内で「今からスタバ／マンモスコーヒー行くけど、みんなもいる？」を投稿し、メンバーが注文、投稿者が受け取り・立て替え、各自が PayPay で送金・投稿者が入金確認するまでを1つのWebアプリで完結させる。目的は **注文の取りまとめを楽にし、支払い漏れをゼロにする** こと。

- 対象: 社内メンバー（スマホ主体、PCブラウザでも利用）
- 店舗: スターバックス / マンモスコーヒー（投稿者が投稿ごとに選択）
- ログイン: **名前だけ**（初回に表示名・PayPay ID・アイコン色を登録、以後は自動ログイン）
- 通知: **新しい投稿** / **締切5分前**
- リポジトリ: `Ryuta0318/coffee-run`（現在は空。ここに新規実装する）

## About the Design Files
`design/Coffee Order v2.dc.html` は **HTMLで作成したデザインリファレンス（動くプロトタイプ）** です。見た目と挙動の正解を示すもので、本番コードとしてそのまま使うものではありません。データは端末内のメモリ／localStorage のみで、共有されません。
タスクは、このデザインを下記推奨スタック（または選定したスタック）で **再実装し、データを全員で共有できるようにする** ことです。

ローカルで開く場合: `design/` フォルダごと静的サーバーで配信し `Coffee Order v2.dc.html` を開く（`support.js` と `_ds/` が同階層に必要）。

## Fidelity
**High-fidelity。** 色・タイポ・余白・角丸・文言・インタラクションは確定。ピクセル単位で再現すること。

- ヘッダー: 「‹ キャンセル」ピル＋小ロゴ。
- Threads風入力: アバター＋タイトル入力（22px/700、初期値は今日の日付「M/D（曜）」）＋本文テキストエリア（初期値「{店名}行きますが皆さんいけますか？」。店舗を変えると自動追従、手で編集したら追従停止）＋サーモン系罫線。
- 「どこで買う？」店舗カード2枚（角丸14px・枠2px、選択中は赤枠＋右上✓）。
- 「注文の締切」チップ: 現在時刻を15分単位で切り上げ＋15分を起点に +0/15/30/45/75分の5択。
- 「出発時間」チップ: 締切と同時 / +10 / +15 / +30分。
- 受取・立替カード: 自分のアバター・名前・PayPay ID＋「変更」（アカウントへ）。
- 「投稿する」ボタン。PayPay ID 未登録時は「PayPay IDを登録して投稿」→押すとアカウント画面へ。

### 4. 投稿詳細
- ヘッダー: 「‹ 投稿一覧」＋小ロゴ。
- 投稿本文（アバター・名前・経過時間・タイトル20px・本文）。
- チケットカード（背景#F3EADF・角丸16px）: 店舗マーク40px、ステータス英字（NOW OPEN・募集中 / CLOSED・受付終了、11px/700/字間0.14em/#A0643C）、店名、右に「締切まで」＋カウントダウン（Archivo Black 26px）。破線区切り（2px dashed #D8C2AC）の下に4列: 注文締切 / 出発 / 注文 n杯 / 合計 ¥n。
- タブ（sticky、ピル型セグメント 背景#F4EEE6・選択中は白＋薄い影）: 注文する / 注文一覧(n) / 精算(未払いn・赤) / チャット(n・茶)。

#### 4a. 注文する
- 参加区分カード2枚: 「一緒に行ける！」（受け取りを手伝います）/「お願いします！」（買ってきてほしい）。
- 注文者行: 自分のアバター32px＋「{名前}さんの注文」＋注文済みなら緑ピル「注文済み」。
- 「いつもの」行（その店で前回注文した内容がある場合）: 破線枠、オレンジピル「いつもの」＋内容＋「これにする」。
- メニュー見出し＋「n品」＋右に「{店名}の公式メニュー ↗」（別タブ: スタバ https://product.starbucks.co.jp/beverage/ / マンモス https://mmth.co.jp/menu）。
- カテゴリチップ（横スクロール）: すべて＋店舗カテゴリ＋その他。
- メニューグリッド2列: 48pxサムネ（種類別の色付きカップアイコン。**公式写真は権利上未使用**。許諾済み画像があれば差し替え）、品名13px/700、`¥最低価格〜・HOT/ICED`。選択中は赤枠＋右上✓。
- 「その他のドリンク」選択時: ドリンク名＋金額の自由入力。
- サイズ（スタバ S/T/G/V、マンモス S/M/L）・温度（HOT/ICED）ピル。提供のない組み合わせは opacity .35・選択不可。
- カスタム・メモ（任意）。
- 下部: お支払い額（24px/700）＋「注文する」/「注文を変更する」ボタン。締切後は「受付終了」で無効。

#### 4b. 注文一覧（主に投稿者用）
- 「一緒に行く」同行者行（破線枠）。
- オンライン注文用まとめ: 同一内容を自動集計（品名 サイズ 温度（メモ） ×数量）。
- 「注文内容をコピー」「受付を締め切る / 受付を再開」。
- 個別注文カード: 頭文字アバター、名前＋区分ピル（一緒に行く=赤地白 / お願い=#F4EEE6地茶）、内容、メモ（#A0643C）、金額、削除×。

#### 4c. 精算
- 回収状況: 確認済み金額 / 合計、プログレスバー10px（赤）、確認済み・報告あり・未払い件数。
- 全員確認済みで緑の完了バナー。
- PayPay送金先カード（投稿者名・ID）。
- 注文ごとの行: 名前＋ステータスピル（未払い / 報告あり / 確認済み）。
  - 本人・未払い →「PayPayで払う」→ ボトムシート
  - 投稿者・報告あり →「入金を確認」
  - 確認済み →「取り消す」
- 「未払いn名にリマインド」（本番ではプッシュ通知またはコピー）。
- **PayPay ボトムシート**: 角丸22px上部、金額40px/700、内容、ステップ①「金額をコピーしてPayPayを開く」（金額をクリップボードへ → PayPayアプリへ遷移。本番は `paypay://` 等のディープリンクを要検証）②「送金しました（報告する）」（①実行後に有効化）→ status=reported。

#### 4d. チャット
- 吹き出し: 自分=右・赤#EF2027・白文字・角丸 18 18 4 18 / 他人=左・#F4EEE6・アバター30px＋名前（連続投稿時は省略）・角丸 18 18 18 4。下に時刻10px。
- 下部固定入力バー: 定型文チップ（了解！/ありがとう！/今どこ？/着きました/追加いいですか？＝タップで即送信）、入力欄44px角丸22px、送信ボタン44px円（入力ありで赤）。Enter送信（IME変換中は除外）。
- 空状態:「まだメッセージはありません。集合場所や追加の注文はここで相談しよう」。

## Interactions & Behavior
- 受付状態 = `closed || now >= deadline_at`。締切を過ぎると自動で受付終了（注文不可）。投稿者は手動で締切／再開可（再開は締切前のみ有効）。
- 1投稿につき1人1注文。再注文は上書き。注文時に `profiles.last_orders[store]` を更新（「いつもの」）。
- 金額は注文時点で `orders.price` に確定保存（メニュー価格改定の影響を受けない）。
- 支払いステータス: unpaid →（本人が報告）reported →（投稿者が確認）done。done → unpaid に戻す操作は投稿者のみ。
- カウントダウンは1秒ごと更新。`m:ss`、1時間以上は `h:mm:ss`。
- Realtime: 投稿一覧・注文・ステータス・チャットは他メンバーの操作が即時反映されること。
- トランジション: 背景/枠色 160ms ease、プログレスバー幅 300ms ease。

## 通知（要件）
1. **新しい投稿**: 投稿作成時、投稿者以外の購読者全員へ Web Push。文面「{名前}さんが{店名}に行きます｜締切 HH:MM」→ タップで投稿詳細へ。
2. **締切5分前**: pg_cron（毎分）で `deadline_at - 5分 <= now() < deadline_at` かつ `notified_5min = false` かつ未締切の投稿を抽出 → 購読者全員へ「締切まであと5分｜{タイトル} {店名}」→ `notified_5min = true`。
- 初回ログイン後に通知許可を求める（iOS はホーム画面追加の案内を先に表示）。
